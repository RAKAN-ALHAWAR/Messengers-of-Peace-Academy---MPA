## Priority findings

Priorities indicate repair order. They do not claim demonstrated server compromise.

### Security and session identity

**S01, P1 investigation priority, recoverable bundled service credential.** Source at
`lib/Data/Database/config/database_end_point.dart:18` includes a credential used
for unauthenticated service functions. It was also exposed during source
inspection. Its value is intentionally omitted. Validity and privileges were
not tested. Distribution in client code makes it recoverable. Rotation/removal
is an OPEN owner decision after checking actual ACLs and public flows. Its
public-endpoint use is intentional in current source. Recovery alone does not
prove privileged access or compromise. A build variable alone cannot protect a
secret shipped in an app. Regression: packaged client contains no privileged
shared credential, and public auth service cannot invoke arbitrary functions.

**S02, P1, protected requests fall back to the shared identity.** Reproduced
locally using the actual endpoint selector with a synthetic credential. At
`database_end_point.dart:29`, absent user token selects the service credential;
login parsing accepts a user ID with no token (`lib/Data/Database/database.dart:53`).
Proposed: reject incomplete auth responses and require a user token for all
protected endpoints. Cross-user server impact is a contract verification gap.

**S03, P1, plaintext persistent session.** Reproduced with the actual Hive class
and a synthetic sentinel: the credential appears verbatim in `app.hive`, has no
default local expiry and remains in file bytes after logical deletion.
`lib/Data/Local/storage/hive.dart:20,55` and
`lib/Core/Controller/App/app_controller.dart:29`. This requires sandbox/backup
file access, not demonstrated access from unrelated ordinary apps. Proposed:
Keychain/Keystore storage and an explicit migration/reauthentication plan;
server revocation must be verified separately.

**S04, P2, unrestricted downloader resource policy.**
`lib/Core/Service/download_file_form_url.dart:16,40` only checks URL absoluteness,
creates Dio without a defined deadline/size/cancel policy, derives extension
from the URL and opens the downloaded file. iOS globally permits arbitrary
loads (`ios/Runner/Info.plist:51`). Proposed: documented HTTPS origins and types,
redirect checks, size/time budgets and cancellation. Use local fixtures; do not
assume all legitimate media works after removing ATS exceptions.

The certificate-bypass helper in `lib/Core/Helper/http_overrides.dart` is unused.
No active TLS-certificate bypass was established.

### Shared data correctness and request lifecycle

**D01, P1/P2, numeric strings silently become defaults.** Reproduced:
`Object? value='11'; value.toIntDefaultX(1)` yields 1; `'75.5'` with the double
helper yields 0. `lib/Core/Extension/convert/convert.dart:72,238` checks
`this is Object` before string parsing. Affects activity numbers, user points,
event timestamps/repeat data and quiz counters when sent as strings. Proposed:
strict typed conversion with tests for null, string, number and invalid input.

**D02, language/API caveat, not an established application defect.** Reproduced:
`dynamic value='11'; value.toIntX` throws `NoSuchMethodError`. The extension is
declared `on dynamic` in the same file. Static `Object?` receivers in model
factory callbacks work through static extension resolution. No active dynamic
receiver was established in the application. Do not count this demonstration
as a production defect or assume model factories are broken.

**D03, P1/P2, completed fetches restart on parent rebuild.** Reproduced with an
actual `FutureBuilderX` widget: fetch calls increase from 1 to 2 after a parent
rebuild with the same inputs. `lib/Ui/Widget/Basic/Utils/future_builder.dart:61`
invokes the callback inside build instead of retaining a Future. Proposed:
cache the Future in state and renew only on explicit refresh/retry or changed
inputs. Check request count, form state and loading transitions across callers.

### Assessment and learning progress

**L01, P1, nullable result answers are discarded then indexed as complete.**
Reproduced parsing failure for null `selectedAnswerIndex` at
`lib/Data/Model/quiz/answer.dart:27`. `ModelUtilX.generateItems` catches and drops
invalid answers (`lib/Core/Helper/model/model.dart:31`), while results access
`answers[i]` rather than matching `slot` (`TestResults/view/view.dart:348`).
Proposed: preserve unanswered entries and join by stable slot, with missing,
reordered and timeout fixtures.

**L02, P1/P2, failed wording can classify as a pass.** Reproduced:
`QuizResultX(passed:'Not passed',...) .isSuccess` is true because it uses
`contains('passed')` (`lib/Data/Model/quiz/quiz_result.dart:16`). Current backend
failure wording is unknown. Proposed: parse the authoritative pass field
explicitly with actual success/failure fixtures, rather than substring matching.

**L03, P1, final submission skips application-status validation.** Source:
`lib/Data/Database/database.dart:594` requests `isSkeepStatus:true`; the remote
adapter accepts explicit `status:error` without `errorcode` in this mode, and
the result controller sets `_isSubmitted=true` (`TestResults/controller/controller.dart:61`).
Proposed: endpoint-specific finalization contract and retry-safe attempt result.
Do not assume changing generic status checks is safe for all quiz endpoints.

**L04, P2, wall-clock time can complete an unwatched video.** Source:
`Course/CourseDetails/controller/controller.dart:112,130,146` counts player route
time and accepts >=5 seconds; paused/loading time counts. A failed request
still sets local completion true. Proposed: agree playback completion rule,
measure actual playback, and require acknowledgement for persisted success.

**L05, P2, summary files have no completion lifecycle.** Source:
`Course/CourseDetails/controller/controller.dart:162` only downloads;
`view/sections/activities.dart:213` omits the completion property. Proposed:
define successful save/open semantics and obtain the resource-completion
endpoint, then update/refetch. Never assume mark-page-completed accepts files.

**L06, P2, totals mix sections, videos and completed topics.** Source:
`Ui/Widget/Custom/Card/course_card.dart:140`,
`Course/CourseDetails/controller/controller.dart:73`,
`view/sections/completion_percentage.dart:56`. File-only and quiz-only courses
produce a video denominator of zero. Proposed: one contract-defined metric for
completed/total units, with separate video counts where useful.

**L07, P2, learning changes do not invalidate Home and course lists.** Source:
`Home/controller/controller.dart:137`, `Course/AllCourses/controller/controller.dart:57`,
`My/MyCourses/controller/controller.dart:23`; Home also has a one-minute cache.
Proposed: explicit route results or shared completion invalidation. Test immediate
return from successful completion to all originating surfaces.

**L08, P2, answer text is used as identity.** Source:
`Test/TestQuestions/view/view.dart:105` and controller line 121 use text then
`indexOf`; duplicate labels always select the first position. Zero-based versus
server-required answer values remains UNVERIFIED. Proposed: stable answer
identifier/value in the contract, including shuffled and duplicate text tests.

**L09, P2, resume loses local answer selection and position.** Source:
`Test/TestQuestions/controller/controller.dart:27,54` initializes question 0 and
all-empty answers for resumed attempts. Proposed: restore persisted answers and
position from the server; exact response fields are not available here.

**L10, P2, timeout races an answer request.** Source:
`Test/TestQuestions/controller/controller.dart:117,156` lets the timer finalize
while a question save is pending, without a shared finalization guard. Proposed:
one state machine for pending save, finalization and navigation; delay the final
answer response beyond the deadline in tests.

**L11, P2, fallback unlock predicate is unreachable with data.** Source:
`Course/AllCourses/controller/controller.dart:22` uses `.map(predicate).isEmpty`;
this checks list length, not any predicate result. Proposed: first decide whether
client-side unlock policy is valid; preserve backend authority.

**L12, P2, empty levels break Home.** Source:
`Home/controller/controller.dart:100` falls back to `levels.first` even when the
list is empty. Proposed: explicit no-assigned-courses state, tested with a new
or unassigned synthetic account.

### Authentication, calendar, profile and notifications

**A01, P1, calendar system-event navigation passes the wrong argument type.**
`Events/CalendarEvents/controller/controller.dart:167` passes `event.id` to a
controller expecting `MeetingX` at `Meeting/MeetingDetails/controller/controller.dart:8`.
Proposed: one typed navigation contract, with a proper ID-to-meeting lookup if
needed; test both calendar and meeting-card entry.

**A02, P1, unconfirmed login loses the user ID.**
`Auth/Login/controller/controller.dart:184` constructs OTP arguments without
userid. OTP sends an empty ID at `Auth/OTP/controller/controller.dart:77` and
later force-unwraps it at line 86. Proposed: obtain and pass the authoritative
ID or support an explicit email-verification contract.

**A03, P1/P2, unsupported Filipino locale.** Reproduced: `DateFormat.MMMM('ph')`
throws `Invalid locale`; installed intl accepts `fil`.
`lib/Config/Translation/translation.dart:28,36,42`. Proposed: UI locale `fil`,
with a separate backend mapping if its API requires `ph`; migrate persisted
language codes and test dated screens in every language.

**A04, P2, meeting join disappears at the scheduled start.** Source:
`lib/Data/Model/meeting.dart:20` treats start time in the past as ended;
`Meeting/MeetingDetails/view/view.dart:98` hides Join. Proposed: authoritative
end/status semantics. Actual backend status values need confirmation.

**A05, P2, date picker leaves stale day's events.** Source:
`Events/CalendarEvents/controller/controller.dart:180` changes date/week but does
not refilter events, unlike weekday/week-arrow handlers. Proposed: one shared
selection method; verify distinct events on two days.

**A06, P2, notification app-bar back clears Home's unread badge incorrectly.**
Source: `Notifications/view/view.dart:22` captures 0 before async fetch; only the
body observes state. `Home/controller/controller.dart:129` trusts that stale
return. Proposed: compute current unread count on back or refetch on return.

**A07, P2, clearing optional profile data emits no clearing instruction.**
Source: `lib/Data/Form/update_user_form.dart:91` and following checks omit empty
Telegram/university/other fields. Proposed: distinguish omitted/unchanged from
explicitly empty, according to server contract.

**A08, P2, image upload failure is reported as profile success.** Source:
`Profile/EditProfile/controller/controller.dart:264` and
`Auth/CompleteAccountInfo/controller/controller.dart:247` swallow upload errors.
Proposed: explicit partial failure and retry, preserving selected image.

**A09, P2, age group uses year subtraction.** Source:
`lib/Data/Form/update_user_form.dart:47` ignores whether the birthday occurred.
A person born 2000-10-18 is still 25 on 2026-10-17 but serializes 26-40.
Proposed: shared exact age calculation, test all bucket boundaries.

**A10, P2, course grades show completion rather than assessment grade.** Source:
`My/MyCertificates/view/sections/course_grades_section.dart:57,59` displays
`completionPercent`. `MyCourse` supplies no actual grade. Proposed: obtain grades
or approve relabeling as progress; never silently present progress as a grade.

Additional smaller findings to retain in the repair backlog: noon uses AM
(`CalendarEvents/controller:102`, `EventDetails/controller:157`); blog dates
hardcode Arabic; old-password and login minimum lengths differ; supported
Spanish names with accents are rejected; event repeat accepts zero/negative
values client-side; deleting an event closes its action sheet but leaves the
deleted detail screen. Backend implications require explicit fixtures.

### Build portability and performance

**B01, P2, three local URIs have wrong filename case.** Source inventory of
303 Dart files found `Model/Basic` instead of `Model/basic` in
`lib/Data/data.dart:46` and `lib/Data/Database/remote/remote_data.dart:8`, plus
`Sections/loading.dart` instead of `sections/loading.dart` in
`lib/Ui/Screen/Profile/EditProfile/view/view.dart:12`. This is a source-confirmed
portability problem for case-sensitive filesystems; no Linux CI run was made.

**P01, P2, Blog fetches the whole archive sequentially.** Reproduced against
actual `DatabaseX.getBlogs` with all HTTP intercepted: 10 articles require 2
requests, 100 require 11, and 1,000 require 101. The last fetch is empty and the
view receives nothing until recursion finishes.
`lib/Data/Database/database.dart:367`. Proposed: fetch one page at a time and
correct the final-page condition. No production latency was measured.

**P02, P2, offscreen list rows are eagerly mounted.** Actual LeaderboardView
at `lib/Ui/Screen/Leaderboard/view/view.dart:53`, viewport 800x600 without
scrolling: 20 entries mount 20 image widgets and 22 fade states; 1,000 entries
mount 1,000 images and 1,002 fade states, including the final offscreen entry.
Proposed: builder/sliver lists and bounded retrieval. Similar patterns in Blog,
Notifications, courses and certificates were source-inspected only. Counts do
not establish iPhone frame time or memory.

**P03, P2, JSON decoding always stays on the calling isolate.**
`lib/Core/Helper/http/lib/response.dart:129` synchronously decodes JSON; no
large-payload isolate boundary exists. Actual adapter, synthetic data, 21 warm
samples per size, Flutter-test debug host, independently repeated by main agent:

| Rows | Body bytes | p50 milliseconds | p95 milliseconds |
| --- | --- | --- | --- |
| 100 | 34,871 | 0.102 | 0.169 |
| 1,000 | 351,671 | 0.992 | 1.937 |
| 10,000 | 3,546,671 | 12.373 | 16.035 |
| 50,000 | 17,866,671 | 56.986 | 59.159 |

These are host measurements, not production payload sizes or iPhone jank.
Proposed: paginate first, decode/map sufficiently large responses in an isolate,
then profile representative iPhone flows. Four performance probes passed:

```sh
flutter test --no-pub --reporter expanded /private/tmp/mopa-audit-probes/performance_test.dart
```

## Proposed repair order, not adopted

1. Agree authentication/service-secret boundary with backend owner; remove shared
   fallback, secure session migration, and cover OTP continuation. Require a safe
   contract and reauthentication/rollback plan before changing shipped sessions.
2. Fix shared conversion/future lifecycle and quiz result integrity with local
   regression tests, then verify complete quiz attempt lifecycle on the account.
3. Agree learning units, minute accounting and completion semantics; fix progress,
   downloads/checkmarks and all originating surfaces against that one contract.
4. Correct calendar/meeting/profile/notification flows and locale handling.
5. Adopt reproducible lock/native build configuration, appropriate CI provider,
   Android/iOS runtime matrix, offline/failure tests and measured performance gates.

No issue should be marked fixed or closed until its acceptance flow is observed
after correction. No production-ready claim follows from this report.
